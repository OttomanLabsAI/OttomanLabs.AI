Under the HOOD what the dashboards are written in · vs Grasshopper & Dynamo
The Stack every dashboard on this site is one HTML file — no framework, no build step, no CAD host

The Gherkin dashboard, the Studio, Dymak HQ — each is a single page of vanilla JavaScript running in the browser. The “3D” views are not a 3D library: the code projects each point to the screen itself, depth-sorts the elements and draws them on a 2D <canvas>. The geometry engine is equally bespoke — the building profile is a real clamped B-spline evaluated with the de Boor algorithm, the same routine inside CAD kernels, hand-written in about forty lines. Python appears only at the edges: the pyRevit add-ins that place the geometry inside Revit.

Two Ways To Compute the deepest difference is not the language — it is what happens when an input changes
Grasshopper / Dynamo · dataflow graph

The program is the graph. Change one input and the engine re-evaluates every downstream node; looping happens implicitly through list-matching rules — powerful, and famously the part that bites even experienced users.

These dashboards · event-driven code

The reactive feel is identical — drag, and the tower updates live — but the loop is explicit imperative code. The full Gherkin (1,540 members, 43 plates) rebuilds and redraws in a few milliseconds.

Why text beats wires here

Grasshopper and Dynamo were invented so non-programmers could build parametric logic without code. With Claude Code writing the JavaScript from a plain-English brief, that reason largely evaporates — and text keeps what graphs are bad at:

Version control that diffs meaningfully · real data structures instead of trees · proper UI for the whole team · logic that does not become wire spaghetti at scale.

Under their canvases, both node editors run on C#/.NET — Grasshopper on Rhino’s RhinoCommon kernel, Dynamo on its DesignScript engine. Here, V8 JIT-compiles the JavaScript; for this scale of arithmetic they sit in the same performance class.

Where the node editors still win, honestly: a mature CAD kernel and its ecosystem — Kangaroo, Ladybug, surface booleans on tap. These pages implement only the maths each tool needs, which is the point: a few hundred lines you fully control, running on anything with a browser, instead of a licensed host. A new geometric operation costs a brief, not a plug-in.
